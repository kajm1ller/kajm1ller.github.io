# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kaj's personal website (GitHub Pages style static pages: `index.html`, `music.html`, `projects.html`, etc.) plus **Kaj Simulator**, a large Three.js open-world driving/on-foot/plane game at `game.html` with optional WebSocket multiplayer. Most development work happens on the game.

## Commands

- `npm install`, then `npm start` (alias `npm run dev` / `npm run server`): runs `server.js` (Express + WebSocket) on `http://localhost:3000`. With Let's Encrypt certs present (`/etc/letsencrypt/live/kaj.services`, overridable via `SSL_CERT_DIR`/`SSL_KEY_PATH`/`SSL_CERT_PATH`) it serves HTTPS on 443 instead. `PORT`, `PUBLIC_PORT`, `PUBLIC_ORIGIN` override.
- Play: open `http://localhost:3000/game.html`. URL params: `?multiplayer=0` disables multiplayer, `?server=ws://host:port` picks another game server, `?time=21.5` starts the day/night clock at that hour (otherwise it follows the wall clock so all clients agree; the E2E runner uses `?time=12`).
- `node tools/buildBars.mjs` re-bakes `js/game/data/bars.json` (the downtown bars' storefronts) from the same OSM extract.
- `npm run build:nav`: re-bakes `js/game/data/cityNav.json` (road graph, sidewalks, furniture, hangouts, typed building doors, parking stalls, drive-through lanes) from the OSM extract via `tools/buildCityNav.mjs` (needs a big heap; script sets 8GB). `tools/buildStreetSigns.mjs` similarly produces `streetSigns.json`, and `tools/buildStreetLamps.mjs` produces `streetLamps.json` (OSM2World lamps already in /mapfinal + new lamps along every lit street).
- Unit tests (Node built-in runner, ESM): `node --test test/unit/` or a single file `node --test test/unit/vehicle.test.js`.
- E2E tests drive headless Edge/Chrome over raw CDP (no Selenium): `node test/run-all-tests.js [--suite=functional|benchmark] [--mock] [--browser=edge|chrome] [--target=<page>] [--frames=N] [--verbose]`. `--mock` runs against `test/mock-game.html`; `BROWSER_PATH` overrides the browser binary. Individual suites: `node test/e2e-functional.test.js`, `node test/e2e-benchmark.test.js`. See `TEST_INFRA.md` for the harness details.
- There is no lint step or bundler in use (`vite.config.js` is vestigial; `server.js` serves the repo root statically).

## Architecture

**No build step.** `game.html` is a ~6.5k-line page whose inline `<script type="module">` imports ES modules directly from `js/game/*.js` (`js/game/package.json` sets `"type": "module"`). Three.js comes from an importmap pointing at unpkg (currently `three@0.160.0`, even though `package.json` lists 0.182) — keep that in mind when using Three APIs. Rapier is copied for local use by `scripts/copy-rapier.js`.

**`js/game/main.js` is the engine core.** It owns the fixed 60 Hz timestep accumulator (`stepSimulation(dt)`), the `SpatialGrid` broadphase (`spatialGrid.js`, 2D hash grid, zero-allocation queries; extents/cell size in `config.js`), and exposes the `window.__GAME__` automation API that both unit tests (`test/unit/gameApi.test.js`) and the CDP E2E tests rely on. Changing that API's shape breaks the test suites and `test/mock-game.html` (a conformance mock).

Other modules in `js/game/` are feature systems consumed by `game.html`: `vehicle.js` / `carModels.js` / `carInterior.js` (kinematic-bicycle car physics, instanced fleets via `instancedFleet.js`), `traffic.js` / `trafficNet.js` / `roadNetwork.js` (IDM car-following + pure-pursuit AI on a lane graph), `pedestrians.js`, `police.js`, `plane.js`, `player.js` / `camera.js`, `guns.js` / `items.js` / `weaponWheel.js`, `environment.js` / `grass.js`, `multiplayer.js` (client).

**Districts.** `districts.js` holds the district boxes traced from `media/districtReference.png` (1 px = 5.44 m, pixel (828, 603) = world (-1829, -625)) and per-district day/night tables (population, who people are, walker kinds, grass/yard and sidewalk scenes, traffic and parking density). `pedestrians.js` spawns from those tables; the scenes themselves (picnics, beer pong, bar lines, fights and arrests, dogs, yardwork...) and their props/poses are in `pedestrianScenes.js`. `parkedCars.js` fills parking stalls / drive-throughs (cars are added to the traffic vehicle list), `airTraffic.js` flies scripted planes in and out of the airport. `window.__DISTRICTS__` (stats, scenes, teleport, free camera `view`) is a debug handle.

**Drugs.** `drugs.js` registers 14 inventory-only drug items plus 3 drinks (Beer, Whiskey, Vodka; kind `drug`) with first-person models, keyframed use animations and effect profiles; `DrugEffects` turns doses into one state (screen, camera, movement, mouse, damage, regen / overdose drain, music speed). `drugFx.js` is the post-processing pass (only active while something is in your system) and exhaled smoke. Psilocybin's visuals scale with how much is in you (`SHROOMS` / `shroomChannels` in drugs.js: `drift` crawling surfaces, `edges` rainbow fringes, `glow` haloes, `snow`, `pattern` filigree over textured surfaces, then from `TAKEOVER_FROM` doses the `takeover` mandala fills the screen; shader in drugFx.js). DMT (one hit, ~3.5 min) follows a fixed timeline taken from `media/dmt.mp4` (`DMT_TRIP` / `dmtChannels` in drugs.js: speckles creeping in, a smear, a green-white burst, hyperspace, dark, back): the hyperspace is three procedural scenes painted after `media/dmt.jpg` (`netField`: the net of galaxy eyes, sculpted faces, the arch tunnel), `dmt2.jpg` (`domeField`: crystal lattice, lotus funnel, star tetrahedra, seed-of-life bell and orbs) and `dmt3.jpeg` (`templeField`: the blacklight temple), each a colour + height field lit as relief (`relief`), melting, breathing and turning (`hyperScene` / `hyperspace` in drugFx.js; `DMT_SCENES` times them); the page's UI is hidden (`body.dmt-hyperspace`), from the smear until you're back nothing you press does anything (`dmtLocked`) and the game's sound is cut (soundFx.js `muteWorld`; only the soundtrack, `__keepAudible`, plays). Coming up, the sound is the game's own through soundFx.js (`dmtChannels` reverb / echo / `pulse` throb / `hum`: `updateDmtHum`; `captureMedia` pulls the already-playing background music in); from the burst the soundtrack `media/dmt-trip.mp3` (the video's audio from the hit on, started at the burst at the same second; `startDmtTripAudio`, kept in step with the dose's clock; the background music gives way). Salvia (`trip: 'salvia'`): a few seconds of pull while the picture folds away like a page (game.html `startSalviaTrip` / `updateSalviaTrip`, `peelCanvas`), then `js/game/salvia/` takes over the loop like Mermaid World (`SalviaWorld`: `enter(kind)`, `frame(dt)`, `finish()`; own scene, camera, captured input, no on-screen text but the air fryer's year 2026 → 3026 in `#salvia-ui`, `body.salvia-trip` hides the HUD) with one of three trips, never the same twice running: `fryerTrip.js` (an air fryer in a kitchen for a thousand years, third person: generations of a family use you, the kitchen ages), `planetTrip.js` (walking a red alien planet, first person), `breadTrip.js` (a loaf from flour through the factory, truck and onto a store shelf, first person on rails). `salviaKit.js`: `Person` (the town's pedestrian rigs drawn as plain meshes, walking / reaching / sitting / eating), `TripSound` (synthesized beds and one-shots), `box` / `cyl`. Debug `__DRUGS__.salvia(kind)` / `__DRUGS__.salvia().finish()`. LSD instead starts the Mermaid World trip (see **Mermaid World** below), which takes over the main loop until you wake up. `window.__DRUGS__` is a debug handle (`dose`, `advance`, `use`, `trip`, `mermaid().finishAll()` which finishes the story and wakes you). Alcohol has its own model in `DrugEffects` (`ALCOHOL`: units soak from `stomach` into `bac`, cleared at `ELIM`/s; tipsy → drunk → hammered with sway, roll, blur, double vision, mouse lag, `stumble()` sideways lurching, `spins`, hiccups and blackout blinks; past `VOMIT` it fires a `'vomit'` event, and drinking after that a `'passout'` event; game.html `updateDrunk` plays the vomiting and the blackout, waking you on a sidewalk a few blocks away hours later, poorer and hungover). Headless Edge renders only a few fps, so E2E scripts should step the simulation by hand when waiting on game-time.

**District streaming.** `districtStreaming.js` (`DistrictStreamer`) keeps only the player's district loaded: pedestrians, traffic (the rest of the fleet goes dormant in `TrafficManager.dormant`), parked / drive-through cars and the airport's planes only exist in it (plus a 60 m margin across the boundary). `?streaming=0` turns it off; `__DISTRICTS__.stats()` shows what is loaded.

**Mermaid World.** `js/game/mermaid/` is a self-contained underwater game with its own scene, camera, UI, audio and save (localStorage `kajsim_mermaid_save_v2`); `MermaidWorld` in `mermaidWorld.js` (`enter`, `frame(dt)`, `active`, `finishAll`, `onExit`) is all game.html touches. The core class holds lifecycle / input / player / camera / frame loop and is extended by mixins: `mermaidWorldNpc.js` (shopkeepers, talking fish, story NPCs, friends, pet, roaming wildlife, schools, all dialogue), `mermaidWorldPlay.js` (collectibles, interaction system with hold-E, training rings and the Ring Run, photo safari, treasure, sea garden, shops and gifts, arcade, temple glyph puzzle, map + fast travel, journal, pause / settings, objective compass / minimap / beacon, Moon Pearl socket) and `mermaidCutscenes.js` (the wedding built from the planner's choices, the Moon Pearl festival, eating at the café). Content lives in `mermaidData.js` (creator options and which are locked behind shop / quest unlocks, wedding planner, shops, friends, areas, minigame numbers) and `mermaidState.js` (`DreamState` save + the quest log: main story dive in / wedding / mall day / snapshot safari / ring run / the Moon Pearl, plus side quests; a step is just `done(S)` and `marker(S)` names what `where()` in the world should point at). Building blocks: `mermaidModel.js` + `mermaidHair.js` + `mermaidFace.js` (the mermaid: lathe torso, canvas-painted face that blinks and talks, 12 hair styles, scaled iridescent tail, fin panels, wardrobe layers), `mermaidCreatures.js` (fish, dolphin, turtle, manta, jelly, octopus, seahorse, crab, shark, whale, puffer, angler), `mermaidEnv.js` (terrain + biomes, procedural caustics, surface shader, light shafts, marine snow, plants / corals / rocks, tide cycle), `mermaidTown.js` / `mermaidWild.js` (the areas), `mermaidUI.js`, `mermaidGames.js` (rhythm, shell match, bubble pop, glyph puzzle), `mermaidAudio.js` (procedural music per area), `mermaidKit.js` (helpers, `Batch` merging, sway shader). Dev tools: `tools/mermaidPreview.html` runs the world without the city map (`?manual=1` + `__MW_STEP__`, `?time=0.7` for night, `?mwlite=1`, `?nobloom=1`; `__MW__.debugCam = { pos, look }` for screenshots) and `tools/mermaidGallery.html` shows mermaids and creatures. Tests: `test/unit/mermaid.test.js`.

**Fist fights.** `brawl.js` is the player side: `PUNCH_MOVES` (jab, cross, hook, uppercut, stomp: wind-up, strike, recover; the blow lands mid-strike), `Brawler` (combo picking with a buffered click, the guard sway / mouse lag / walk bob / move poses of the two-fist viewmodel and the stomping leg, a camera kick) and `findWallAhead`. game.html (`throwPunch` / `landBlow` / `toggleGrab` (G) / `pinToWall` (F) / `updateBrawl`) wires it up; pinning also falls back to `impacts.raycastWorld` where walls have no collider box (around the spawn). pedestrians.js adds the `downed` state (knocked down by heavy blows, writhing, getting back up to fight or flee; hits keep them down, a killing blow hands them to the ragdoll already lying flat via `_dieOnGround`) and `held` (`grab` / `setHeld` / `release`: dragged on their feet or by the wrists when lying, or pinned to a wall; they wriggle free unless kept busy). Pinned people stay pinned and can not be punched below 1 hp; `bruiseFace` adds face-damage parts (blood, swelling, cuts, a smashed face) and each punch paints the wall (`pinnedBlood`). With a gun out (F pins with one too) the gun goes to their temple and the shot is `executePinned` (`goreHead` swaps the head for a stump, big splatter on the wall). G holds a standing person by the throat in front of you (`neck`); sprinting, holding the fist down and letting go near someone tackles them (`tryTackle` / `updateTackle`) onto their back with you astride (`mount`: punches and the gun work as on a wall); G from there drags them by the wrists in third person (`dragCam`, your body is `kajBody`, a pedestrian rig in `extraRigs`), F gets up. Dropped off a wall or killed against it, they slide down it and sit (`downPose` `wall`, `slumpDead`, blood trail `startWallSlide`). On foot, `cameraController.update` runs before `updatePlayer` so the camera built there (stride bob, ground level, third person) is the one drawn. Multiplayer: people the region's owner simulates are acted on with `cmd` `brawl` (`hold` / `release` / `knock` / `exec`; `handleBrawlCmd`, the grabber drives a replica with `ped.net.local`), their fight state rides in the owner's snapshots (`brawlRecord` in pedestrians.js), and blood / gore / wall slides are `rel` `brawlFx`; other players are grabbed, pinned, tackled, dragged and executed with `direct` `hold` / `release` / `exec` / `broke` (`pvp` holds them, `victim` is being held: left click punches back, `escape`), each side drawing the other from its own state (`RemotePlayers` entry `override`), and the update's `brawl` / `face` / `nohead` fields tell everyone else. Police (police.js) hold you at gunpoint and only shoot once you fire (`weaponsFree`, `playerFired`); cruisers stop short of someone on foot. Debug handle `__BRAWL__` (`spawnAhead`, `grab`, `pin`, `tackle`, `knockDown`, `look`, `wallProbe`, `brawler`). The fists ride springs (`_spring`), every punch is varied a little, a landed blow hit-stops (`impact`), a miss over-reaches (`whiff`) and heavy punches step you in (`takeLunge`); NPC flinches depend on `hit.move`. Tests: `test/unit/brawl.test.js`, `brawlPeds.test.js`.

**Carjacks, gore, crashes.** People getting out of a car are real pedestrians from `PedestrianSystem.driverOut` (state `carjacked`, `ai.carOut`: keyframed seated → ducking out of the door → standing, then `fleeing`; the same look riders.js showed at the wheel, `npcOccupants`): `pulled` for the E carjack (`startCarjackAnimation`), `hands` for a hold-up (game.html `updateHoldups`: on foot, a gun aimed at a car with a driver within `HOLDUP_RANGE` for `HOLDUP_AIM_TIME`; the car pulls up, the driver pushes the door open with their hands up, backs off and runs, the car is left running with the door open). Debug `__CARJACK__`. Shotguns blow off heads, arms and legs within `GORE_RANGE` (`shotgunGore` / `blowOff`, alive or dead; `goreLimb` leaves a stump, `limbMesh` is the loose limb that flies and lands, `severed`; `limbsGone` rides in `brawlRecord`). Debug `__GORE__`. The pump shotgun is racked by hand between shots (`rackPump`: wheel down / up, `stack.data.pump` 'spent' / 'open' / 'ready'; sounds `media/shotgun-pump-back.mp3` / `-forward.mp3`, cut from `shotgun-pumping.mp3`; touch screens rack it automatically). A car that loses `EJECT_SPEED` within a few steps throws you through the windshield (`watchForEjection` / `ejectThroughWindshield`, the player ragdoll with `playerAction.eject`; the landing kills you) unless you're belted in: `seatbelt.js` (`Seatbelt`, on the car's mesh, reset every time you get in) has you look over your left shoulder in the driver's view, click the tongue, drag it across and let go over the buckle by your right hip (`grab` / `release`; touch screens buckle up by themselves); unbuckled with the engine on, the car dings (`playBeltDing`) and the cluster shows a lamp (`vehicle.beltWarning`, carInterior.js `Cluster.draw`). A sudden speed change throws the driver's view forward and back (`updateWhiplash`). Building colliders whose box crosses a road centreline are not registered (mapLoader.js `crossesBox`), so cars don't hit invisible walls. Debug `__EJECT__` (`belt()`, `watch`, `whip`).

**Dropped things.** `propPhysics.js` (`PropPhysics`): rigid box colliders against `impacts.raycastWorld` (+ bars' upstairs floors) that fall, bounce, tip over and sleep. Q on foot (game.html `dropHeld`) drops the held item (one off a pile) as its own model (`buildItemWorldModel`: gun model / `buildDrugWorldModel`), or $20 cash with nothing droppable in hand (`CashDrops` bills are bodies too); holding Q charges a throw (`throwPower`) and a thrown thing in flight knocks down or kills whoever it hits (`updateThrown`, via `punchPed`). E picks things up (`itemPrompt`). Local only. Debug `__ITEMS__`.

**Gun handling.** `gunMotion.js` (`GunMotion`, debug `__GUNS__`) poses the first-person gun on springs from the walking state (hip carry with a figure-eight bob, a canted sprint carry that drops out when you aim / fire / reload, mouse-trailing sway, strafe lean, breathing, shot kick; heavier guns are slower, `gunWeight`), plays staged magazine reloads (`reloadPlan`: mag out, mag seated (the rounds go in then), rack only when it ran dry; game.html `updateReload` times the sounds and ammo off the same plan) and shell-by-shell ones, and switching (`startSwitch`: the held thing is lowered out of view (`switchFrom`), the next drawn; no firing / aiming / reloading until it's up, `ready`). It moves the gun models' named parts from guns.js (`gun_mag`, `gun_slide`, `gun_bolt`, `gun_rocket`). `selectWeapon` (code / test API) skips the draw. `inventory.lock` blocks switching while a shotgun's pump is pulled back. Other players' bodies carry guns across the chest at a run (`poseHold` `run`). Tests: `test/unit/gunMotion.test.js`.

**Phones and tablets.** game.html's MOBILE CONTROLS section (`isMobile`, `body.is-mobile`): a floating analogue stick wherever the left thumb lands (`#m-move-zone`; on foot it fills `touchMove`, which `updatePlayer` reads instead of WASD (`footMotion` scales by how far it's pushed, the edge runs); in a car it steers through `playerController.analog` (player.js: analogue throttle / brake / steer for cars) with the `#m-gas` / `#m-brake` pedals (slide up a pedal to press harder); in a plane it banks / pitches with the `#m-throttle` lever), drag on the right half to look (`touchLook`, acceleration, `kajsim.lookSens`), round buttons round the fire button (`.mb`, shown per `mode-foot / mode-car / mode-plane` and held weapon `w-gun / w-hands / ...` via `data-modes` / `data-w`; fire and aim also look while dragged; Use lights up when there's a prompt), a top bar (`#m-weapon`: tap next, hold the wheel; `#m-menu` sheet of tiles built by `buildMobileMenu`), a turn-sideways screen in portrait, full screen + landscape lock on the first touch. Buttons call the game's functions; E and the mouse buttons are synthesized events (`tapVirtualKey`, `fireMouse`). `updateMobileJoystick` runs each step. Phones get resolution that follows the frame rate (`dynRes`, `updateDynamicResolution`). Performance: `scene.matrixAutoUpdate = false` and the map / tree / street-sign roots are frozen after load (their per-frame matrix updates were forcing every object's world matrix to be recomputed, about a third of a phone's frame); map / tree / sign visibility is only recomputed when the camera has moved a few metres.

**Walking.** `footMotion.js` (`FootMotion`) gives on-foot movement velocity (acceleration, normalised diagonals, walls eat speed) and a stride phase that drives the head bob / sway / lean, the viewmodel bob and the footstep sounds; `updatePlayer` in game.html calls `update` then `afterMove`.

**Money.** `money.js` has the `Wallet` (localStorage, `charge()` for bills and fines), the HUD and `CashDrops` (bills left by dead people). `__MONEY__` is the debug handle.

**Kaj Arcade (phone app).** `arcade/` is a standalone installable PWA (`arcade/index.html`, `manifest.webmanifest`, `sw.js`, icons made by `icons/make-icons.js`) at `/arcade/`. It holds the 16 play-money games and the bank: `arcadeUI.js` (lobby + game screen + the `ctx` every game gets), `wallet.js` (own balance, localStorage `kajarcade.wallet.v1`, no three.js), `cards.js`, `sfx.js` and `games/*.js` (each `{ id, name, mount(stage, ctx) }`). Bump `VERSION` in `sw.js` when its files change. In `game.html` the phone is a 3D viewmodel object (Up arrow pulls it out, on foot or driving in the driver's-seat view, not the chase camera; arrows / Enter / Backspace navigate; screen = canvas texture, apps: Casino, Maps, Wallet, Clock). The Casino app is `arcade/index.html?embed=1` in an iframe pinned onto the phone's screen each frame at the angle it's held (`pinAppToPhone()`, a CSS matrix3d from the projected screen corners); it uses the game's `Wallet` via `window.__KAJ_WALLET__`. The game keeps the mouse and keyboard (you keep walking / driving); the phone keys are forwarded to `ArcadeUI.navKey()` (arrows move a highlight between buttons, Enter presses / adjusts a slider, Backspace goes back). Game maths is unit tested (`test/unit/arcade.test.js`). Debug handle `__ARCADE__`.

**Downtown bars.** `bars.js` (with `barKit.js`: canvas textures, materials that look lit from inside, and `Kit`, which merges a bar into one mesh per material) models the real OSM bars in the Downtown Bars district inside and out (`data/bars.json`, baked by `tools/buildBars.mjs`: footprints split per storefront where several bars share a building, overlaps between neighbours split down the middle, `fillers` for the rest of a carved building). Each bar's look and layout is a `SPECS` entry (facade, wall / floor / ceiling finish, counter and back bar, zones such as seating, booths, pool, darts, stage with band gear, LED dance floor + mirror ball + DJ, arcade, kitchen window, Tubby's back room, the Cla-Zel lobby and theatre stage, The Attic's patio), drawn from what's known about each place. `carve` cuts the map's own buildings out (tile triangles entirely inside, and their colliders). Uptown and The Attic are upstairs with their own street door and stairs: `floorAt(x, z, y)` sets the player's height (called from `updatePlayer`; colliders carry y ranges, so each floor has its own walls). Bar people are real pedestrians (`PedestrianSystem.spawnControlled`, state `'bar'`, run by `Bars.updatePed`: guests come in off the street, order, sit, mingle, dance, play pool / darts / arcade, use the restroom and leave; staff work, a bouncer by the door), so they can be shot, punched, talked to and killed. `trouble(x, z, y, kind)` (called by game.html on a punch or gunshot in a bar) sends the bouncer and the nearest few guests to fight you and the rest out of the door. The bars are only open at night (`BAR_CONFIG.OPEN_NIGHT` on `nightFactor`): staff and a packed crowd (capped by floor area) are pedestrian rigs in `PedestrianSystem.extraRigs` in the nearest `CROWDED_BARS` storefronts within 14 m, and `BarAudio` plays each bar's own song from `media/barmusic/` (`BAR_CONFIG.MUSIC`; add new files there) (bass-boosted: low shelf + sub peak) over `media/CrowdTalking.mp3`, clear inside the bar's room and low-passed / quieter outside (fading out by `HEAR_DISTANCE`); game.html creates the AudioContext when `barSystem.wantsAudio`. By day they're empty and silent; the game's background music pauses while a bar is in earshot. `alignDoors(nav)` moves the walking nav's bar doors (cityNav.js `moveDoor`) onto the modelled entrances, so the street queues and bouncers line up at the real doors. E at a counter opens the drinks menu (1-3: Beer $5, Whiskey $7, Vodka $8; the drink goes in your hand). Debug handle `__BARS__` (`list`, `goTo('howard')`, `stats`, `order`). Tests: `test/unit/bars.test.js`.

**Sound effects bus.** `soundFx.js` reroutes everything bound for `ctx.destination` through a bus whose reverb / echo (drunk) are only wired in while turned up; only long-running `<audio>` (music, radio, loops) is captured into it, never one-shot clips (capturing every clone piled up nodes and broke the audio up).

**Car crashes.** `carCrash.js` (`CrashSystem`, run each step from game.html over every car near the player) detects car-on-car contact from each car's last-frame velocity (the player car's own push-apart in vehicle.js has already eaten the closing speed by then), exchanges momentum with a spin, makes traffic / parked cars hit hard into wrecks (`driverGone`, so traffic.js retires the driver; the crash system slides them to a stop), dents both cars (each gets its own geometry copy and is shown with its own mesh, which hides its instancedFleet copy), breaks the window on the struck side, throws sparks and debris, smokes damaged bonnets and saps a damaged car's power (`damage`, read in vehicle.js `setInputs`). `CrashAudio` synthesises the crashes and the thunk of a pedestrian being hit / landing on a car; witnesses' screams are real recordings (`media/screams/scream_01..11.mp3`, CC0, sources in `media/screams/CREDITS.txt`; `SCREAM_CLIPS` in carCrash.js) (`witnessesReact` in game.html also sends them running). Debug handle `__CRASH__` (`stats`, `ram(speed)`, `look(x, z)`).

**Gas stations.** `gasStations.js` builds a store and pump canopy at each real OSM `amenity=fuel` site (`data/gasStations.json`, baked by `tools/buildGasStations.mjs`), cutting the map's own building out of the tile meshes and spatial grid (`carve`). Hold a gun at the counter and press E to rob the clerk (reports `armed_robbery`); clerks are shootable (`targets()` / `hurtClerk()`). Local only, not synced in multiplayer. Debug handle `__GAS__` (`list`, `goTo(i, lx, lz)`, `rob`). Tests: `test/unit/gasStations.test.js`.

**Map.** `cityMap.js` draws the town map from `data/streetMap.json` (roads with names, rails, water, parks, street labels; baked by `tools/buildStreetMap.mjs`). N opens the Maps app on the in-game phone (the map is drawn onto the phone's screen; arrows pan, Enter zooms; radio skip is Shift+N); the heading-up minimap is toggled in the dev menu (saved in localStorage `kajsim.minimap`).

**Shared world (multiplayer).** The map is cut into regions (`computeNetRegion` in game.html: a district, or a 1.5 km square of the outskirts). `multiplayerServer.js` makes the first player to join a region its owner and relays the owner's `world` snapshots to the rest of the region; `netWorld.js` builds them (`NetOwner`: people, scene props, dogs, all cars, delta-coded) and draws them (`NetReplica`; `PedestrianSystem` / `TrafficManager` / `ParkedCars` have a `replicaMode` in which they don't simulate). Acting on a replica is a `cmd` to the owner; deaths, ragdolls and cash are `rel` / `drop` events. Each player's police are sent to players near them (`NetCops`) and drawn as ghosts. The server also holds the clock, cash-pickup arbitration and car seats: you can `board` another player's car (E) and give NPCs a lift (G, `riders.js`); traffic cars show their driver and passengers. Server protocol is documented at the top of `multiplayerServer.js`; `__NET__` is the debug handle (`stats()`, `peds()`, `board(id)`, `killNearest()`). Tests: `test/unit/sharedWorldServer.test.js`, `netWorld.test.js`.

**Map data.** The world is the `/mapfinal` OBJ terrain (large; world coords roughly x −9975..5925, z −8968..7472, so `WORLD_HALF_SIZE` is 10000). `newmap2/` and `anothermapo/` are earlier/alternate OSM2World exports (`map.osm` + `part*.obj`). Navigation data (`js/game/data/cityNav.json`) is baked offline from the same OSM extract the visual map came from, so the two must stay in sync — re-run `npm run build:nav` if the map changes.

**Servers.** `server.js` = static files + API routes (Spotify OAuth, Google-TTS `/api/bedroom-voice`, etc.) and attaches `multiplayerServer.js`, which shares the HTTP(S) server for `ws(s)://<same host>`. The protocol (join/update/chat/fire/shoot/event/died client→server; welcome/players/chat/shot/event/hit/kill/full server→client) is documented at the top of `multiplayerServer.js`. Only player state is synced; traffic, pedestrians and police are simulated independently per client.
