# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Kaj's personal website (GitHub Pages style static pages: `index.html`, `music.html`, `projects.html`, etc.) plus **Kaj Simulator**, a large Three.js open-world driving/on-foot/plane game at `game.html` with optional WebSocket multiplayer. Most development work happens on the game.

## Commands

- `npm install`, then `npm start` (alias `npm run dev` / `npm run server`): runs `server.js` (Express + WebSocket) on `http://localhost:3000`. With Let's Encrypt certs present (`/etc/letsencrypt/live/kaj.services`, overridable via `SSL_CERT_DIR`/`SSL_KEY_PATH`/`SSL_CERT_PATH`) it serves HTTPS on 443 instead. `PORT`, `PUBLIC_PORT`, `PUBLIC_ORIGIN` override.
- Play: open `http://localhost:3000/game.html`. URL params: `?multiplayer=0` disables multiplayer, `?server=ws://host:port` picks another game server, `?time=21.5` starts the day/night clock at that hour (otherwise it follows the wall clock so all clients agree; the E2E runner uses `?time=12`).
- `node tools/buildBars.mjs` re-bakes `js/game/data/bars.json` (the downtown bars' storefronts) from the same OSM extract.
- `npm run build:nav`: re-bakes `js/game/data/cityNav.json` (road graph, sidewalks, furniture, hangouts, typed building doors, parking stalls, drive-through lanes) from the OSM extract via `tools/buildCityNav.mjs` (needs a big heap; script sets 8GB). `tools/buildStreetSigns.mjs` similarly produces `streetSigns.json`, and `tools/buildStreetLamps.mjs` produces `streetLamps.json` (OSM2World lamps already in /mapfinal + new lamps along every lit street).
- Unit tests (Node built-in runner, ESM): `node --test test/unit/` or a single file `node --test test/unit/vehicle.test.js`.
- E2E tests drive headless Edge/Chrome over raw CDP (no Selenium): `node test/run-all-tests.js [--suite=functional|benchmark] [--mock] [--browser=edge|chrome] [--target=<page>] [--frames=N] [--verbose]`. `--mock` runs against `test/mock-game.html`; `BROWSER_PATH` overrides the browser binary. Individual suites: `node test/e2e-functional.test.js`, `node test/e2e-benchmark.test.js`. See `TEST_INFRA.md` for the harness details.
- There is no lint step or bundler in use (`vite.config.js` is vestigial; `server.js` serves the repo root statically).

## Architecture

**No build step.** `game.html` is a ~6.5k-line page whose inline `<script type="module">` imports ES modules directly from `js/game/*.js` (`js/game/package.json` sets `"type": "module"`). Three.js comes from an importmap pointing at unpkg (currently `three@0.160.0`, even though `package.json` lists 0.182) — keep that in mind when using Three APIs. Rapier is copied for local use by `scripts/copy-rapier.js`.

**`js/game/main.js` is the engine core.** It owns the fixed 60 Hz timestep accumulator (`stepSimulation(dt)`), the `SpatialGrid` broadphase (`spatialGrid.js`, 2D hash grid, zero-allocation queries; extents/cell size in `config.js`), and exposes the `window.__GAME__` automation API that both unit tests (`test/unit/gameApi.test.js`) and the CDP E2E tests rely on. Changing that API's shape breaks the test suites and `test/mock-game.html` (a conformance mock).

Other modules in `js/game/` are feature systems consumed by `game.html`: `vehicle.js` / `carModels.js` / `carInterior.js` (kinematic-bicycle car physics, instanced fleets via `instancedFleet.js`), `traffic.js` / `trafficNet.js` / `roadNetwork.js` (IDM car-following + pure-pursuit AI on a lane graph), `pedestrians.js`, `police.js`, `plane.js`, `player.js` / `camera.js`, `guns.js` / `items.js` / `weaponWheel.js`, `environment.js` / `grass.js`, `multiplayer.js` (client).

**Districts.** `districts.js` holds the district boxes traced from `media/districtReference.png` (1 px = 5.44 m, pixel (828, 603) = world (-1829, -625)) and per-district day/night tables (population, who people are, walker kinds, grass/yard and sidewalk scenes, traffic and parking density). `pedestrians.js` spawns from those tables; the scenes themselves (picnics, beer pong, bar lines, fights and arrests, dogs, yardwork...) and their props/poses are in `pedestrianScenes.js`. `parkedCars.js` fills parking stalls / drive-throughs (cars are added to the traffic vehicle list), `airTraffic.js` flies scripted planes in and out of the airport. `window.__DISTRICTS__` (stats, scenes, teleport, free camera `view`) is a debug handle.

**Drugs.** `drugs.js` registers 14 inventory-only drug items plus 3 drinks (Beer, Whiskey, Vodka; kind `drug`) with first-person models, keyframed use animations and effect profiles; `DrugEffects` turns doses into one state (screen, camera, movement, mouse, damage, regen / overdose drain, music speed). `drugFx.js` is the post-processing pass (only active while something is in your system) and exhaled smoke. LSD instead starts the Mermaid World trip (`js/game/mermaid/`: data, model, UI, world), which takes over the main loop until its three tasks are done. `window.__DRUGS__` is a debug handle (`dose`, `advance`, `use`, `trip`, `mermaid().finishAll()`). Alcohol has its own model in `DrugEffects` (`ALCOHOL`: units soak from `stomach` into `bac`, cleared at `ELIM`/s; tipsy → drunk → hammered with sway, roll, blur, double vision, mouse lag, `stumble()` sideways lurching, `spins`, hiccups and blackout blinks; past `VOMIT` it fires a `'vomit'` event, and drinking after that a `'passout'` event; game.html `updateDrunk` plays the vomiting and the blackout, waking you on a sidewalk a few blocks away hours later, poorer and hungover). Headless Edge renders only a few fps, so E2E scripts should step the simulation by hand when waiting on game-time.

**District streaming.** `districtStreaming.js` (`DistrictStreamer`) keeps only the player's district loaded: pedestrians, traffic (the rest of the fleet goes dormant in `TrafficManager.dormant`), parked / drive-through cars and the airport's planes only exist in it (plus a 60 m margin across the boundary). `?streaming=0` turns it off; `__DISTRICTS__.stats()` shows what is loaded.

**Money.** `money.js` has the `Wallet` (localStorage, `charge()` for bills and fines), the HUD and `CashDrops` (bills left by dead people). `__MONEY__` is the debug handle.

**Kaj Arcade (phone app).** `arcade/` is a standalone installable PWA (`arcade/index.html`, `manifest.webmanifest`, `sw.js`, icons made by `icons/make-icons.js`) at `/arcade/`. It holds the 16 play-money games and the bank: `arcadeUI.js` (lobby + game screen + the `ctx` every game gets), `wallet.js` (own balance, localStorage `kajarcade.wallet.v1`, no three.js), `cards.js`, `sfx.js` and `games/*.js` (each `{ id, name, mount(stage, ctx) }`). Bump `VERSION` in `sw.js` when its files change. In `game.html` the phone is a 3D viewmodel object (Up arrow pulls it out, on foot or driving in the driver's-seat view, not the chase camera; arrows / Enter / Backspace navigate; screen = canvas texture, apps: Casino, Maps, Wallet, Clock). The Casino app is `arcade/index.html?embed=1` in an iframe pinned onto the phone's screen each frame at the angle it's held (`pinAppToPhone()`, a CSS matrix3d from the projected screen corners); it uses the game's `Wallet` via `window.__KAJ_WALLET__`. The game keeps the mouse and keyboard (you keep walking / driving); the phone keys are forwarded to `ArcadeUI.navKey()` (arrows move a highlight between buttons, Enter presses / adjusts a slider, Backspace goes back). Game maths is unit tested (`test/unit/arcade.test.js`). Debug handle `__ARCADE__`.

**Downtown bars.** `bars.js` (with `barKit.js`: canvas textures, materials that look lit from inside, and `Kit`, which merges a bar into one mesh per material) models the real OSM bars in the Downtown Bars district inside and out (`data/bars.json`, baked by `tools/buildBars.mjs`: footprints split per storefront where several bars share a building, overlaps between neighbours split down the middle, `fillers` for the rest of a carved building). Each bar's look and layout is a `SPECS` entry (facade, wall / floor / ceiling finish, counter and back bar, zones such as seating, booths, pool, darts, stage with band gear, LED dance floor + mirror ball + DJ, arcade, kitchen window, Tubby's back room, the Cla-Zel lobby and theatre stage, The Attic's patio), drawn from what's known about each place. `carve` cuts the map's own buildings out (tile triangles entirely inside, and their colliders). Uptown and The Attic are upstairs with their own street door and stairs: `floorAt(x, z, y)` sets the player's height (called from `updatePlayer`; colliders carry y ranges, so each floor has its own walls). Bar people are real pedestrians (`PedestrianSystem.spawnControlled`, state `'bar'`, run by `Bars.updatePed`: guests come in off the street, order, sit, mingle, dance, play pool / darts / arcade, use the restroom and leave; staff work, a bouncer by the door), so they can be shot, punched, talked to and killed. `trouble(x, z, y, kind)` (called by game.html on a punch or gunshot in a bar) sends the bouncer and the nearest few guests to fight you and the rest out of the door. The bars are only open at night (`BAR_CONFIG.OPEN_NIGHT` on `nightFactor`): staff and a packed crowd (capped by floor area) are pedestrian rigs in `PedestrianSystem.extraRigs` in the nearest `CROWDED_BARS` storefronts within 14 m, and `BarAudio` plays each bar's own song from `media/barmusic/` (`BAR_CONFIG.MUSIC`; add new files there) (bass-boosted: low shelf + sub peak) over `media/CrowdTalking.mp3`, clear inside the bar's room and low-passed / quieter outside (fading out by `HEAR_DISTANCE`); game.html creates the AudioContext when `barSystem.wantsAudio`. By day they're empty and silent; the game's background music pauses while a bar is in earshot. `alignDoors(nav)` moves the walking nav's bar doors (cityNav.js `moveDoor`) onto the modelled entrances, so the street queues and bouncers line up at the real doors. E at a counter opens the drinks menu (1-3: Beer $5, Whiskey $7, Vodka $8; the drink goes in your hand). Debug handle `__BARS__` (`list`, `goTo('howard')`, `stats`, `order`). Tests: `test/unit/bars.test.js`.

**Sound effects bus.** `soundFx.js` reroutes everything bound for `ctx.destination` through a bus whose reverb / echo (drunk) are only wired in while turned up; only long-running `<audio>` (music, radio, loops) is captured into it, never one-shot clips (capturing every clone piled up nodes and broke the audio up).

**Car crashes.** `carCrash.js` (`CrashSystem`, run each step from game.html over every car near the player) detects car-on-car contact from each car's last-frame velocity (the player car's own push-apart in vehicle.js has already eaten the closing speed by then), exchanges momentum with a spin, makes traffic / parked cars hit hard into wrecks (`driverGone`, so traffic.js retires the driver; the crash system slides them to a stop), dents both cars (each gets its own geometry copy and is shown with its own mesh, which hides its instancedFleet copy), breaks the window on the struck side, throws sparks and debris, smokes damaged bonnets and saps a damaged car's power (`damage`, read in vehicle.js `setInputs`). `CrashAudio` synthesises the crashes and the thunk of a pedestrian being hit / landing on a car; witnesses' screams are real recordings (`media/screams/scream_01..11.mp3`, CC0, sources in `media/screams/CREDITS.txt`; `SCREAM_CLIPS` in carCrash.js) (`witnessesReact` in game.html also sends them running). Debug handle `__CRASH__` (`stats`, `ram(speed)`, `look(x, z)`).

**Gas stations.** `gasStations.js` builds a store and pump canopy at each real OSM `amenity=fuel` site (`data/gasStations.json`, baked by `tools/buildGasStations.mjs`), cutting the map's own building out of the tile meshes and spatial grid (`carve`). Hold a gun at the counter and press E to rob the clerk (reports `armed_robbery`); clerks are shootable (`targets()` / `hurtClerk()`). Local only, not synced in multiplayer. Debug handle `__GAS__` (`list`, `goTo(i, lx, lz)`, `rob`). Tests: `test/unit/gasStations.test.js`.

**Map.** `cityMap.js` draws the town map from `data/streetMap.json` (roads with names, rails, water, parks, street labels; baked by `tools/buildStreetMap.mjs`). N opens the Maps app on the in-game phone (the map is drawn onto the phone's screen; arrows pan, Enter zooms; radio skip is Shift+N); the heading-up minimap is toggled in the dev menu (saved in localStorage `kajsim.minimap`).

**Shared world (multiplayer).** The map is cut into regions (`computeNetRegion` in game.html: a district, or a 1.5 km square of the outskirts). `multiplayerServer.js` makes the first player to join a region its owner and relays the owner's `world` snapshots to the rest of the region; `netWorld.js` builds them (`NetOwner`: people, scene props, dogs, all cars, delta-coded) and draws them (`NetReplica`; `PedestrianSystem` / `TrafficManager` / `ParkedCars` have a `replicaMode` in which they don't simulate). Acting on a replica is a `cmd` to the owner; deaths, ragdolls and cash are `rel` / `drop` events. Each player's police are sent to players near them (`NetCops`) and drawn as ghosts. The server also holds the clock, cash-pickup arbitration and car seats: you can `board` another player's car (E) and give NPCs a lift (G, `riders.js`); traffic cars show their driver and passengers. Server protocol is documented at the top of `multiplayerServer.js`; `__NET__` is the debug handle (`stats()`, `peds()`, `board(id)`, `killNearest()`). Tests: `test/unit/sharedWorldServer.test.js`, `netWorld.test.js`.

**Map data.** The world is the `/mapfinal` OBJ terrain (large; world coords roughly x −9975..5925, z −8968..7472, so `WORLD_HALF_SIZE` is 10000). `newmap2/` and `anothermapo/` are earlier/alternate OSM2World exports (`map.osm` + `part*.obj`). Navigation data (`js/game/data/cityNav.json`) is baked offline from the same OSM extract the visual map came from, so the two must stay in sync — re-run `npm run build:nav` if the map changes.

**Servers.** `server.js` = static files + API routes (Spotify OAuth, Google-TTS `/api/bedroom-voice`, etc.) and attaches `multiplayerServer.js`, which shares the HTTP(S) server for `ws(s)://<same host>`. The protocol (join/update/chat/fire/shoot/event/died client→server; welcome/players/chat/shot/event/hit/kill/full server→client) is documented at the top of `multiplayerServer.js`. Only player state is synced; traffic, pedestrians and police are simulated independently per client.
